# EVENT CREW Landing Page — Design Specification

## Цель

Создать современный одностраничный сайт EVENT CREW для подбора персонала на мероприятия в Москве. Первая версия должна выглядеть законченной, корректно работать на desktop, планшетах и мобильных устройствах, отправлять заявки в Telegram и позволять быстро заменять тексты, контакты, услуги, проекты и фотографии.

Референс BigBoy Events используется только как ориентир по крупной типографике, масштабу фотографий и ритму секций. Композиция, палитра и визуальные детали EVENT CREW остаются самостоятельными.

## Визуальное направление

- Направление: светлый редакционный минимализм с ощущением премиального event-сервиса.
- Палитра: молочный фон, черный и почти черный текст, фирменный желтый акцент из предоставленного логотипа.
- Логотип: исходный квадратный знак EVENT CREW используется в шапке; адаптивный размер сохраняет читаемость рамки и желтой вертикали. Тот же знак используется в footer и при подготовке Open Graph-изображения.
- Типографика: крупный плотный гротеск для заголовков, нейтральный хорошо читаемый гротеск для основного текста.
- Изображения: реалистичные фотографии мероприятий и event-персонала без видимых логотипов, вымышленных клиентов и узнаваемых брендов.
- Формы: большие изображения, мягкие скругления карточек, много свободного пространства, тонкие линии и ясная визуальная иерархия.
- Эффекты: умеренное появление элементов при прокрутке, небольшой zoom фотографий на hover, плавные состояния кнопок и анимированное мобильное меню.
- Доступность движения: при `prefers-reduced-motion` декоративные переходы отключаются или сокращаются.

## Структура страницы

### Header

Фиксированная полупрозрачная шапка содержит квадратный логотип, ссылки «Услуги», «Почему мы», «Проекты», «Как мы работаем», «Контакты» и кнопку «Оставить заявку». Ссылки выполняют плавную прокрутку. На мобильных устройствах навигация раскрывается в анимированное полноэкранное меню, закрывается после выбора ссылки и возвращает фокус на кнопку открытия.

### Hero

Первый экран занимает 90–100vh. Слева расположен единственный `h1`: «Персонал для вашего мероприятия», подзаголовок о подборе персонала в Москве и CTA «Рассчитать стоимость». Справа находится крупная временная фотография мероприятия. CTA прокручивает к форме.

### Услуги

Адаптивная сетка отображает восемь услуг: хостес, промоутеры, хелперы, официанты, координаторы, гардеробщики, регистраторы и аниматоры. Каждая карточка содержит локальную фотографию, название и краткое описание. Карточки создаются через `map()` из массива данных.

### Почему мы

Четыре карточки объясняют быстрый подбор, контроль выхода, оперативную замену и индивидуальный подход. Блок содержит подпись «Работаем с мероприятиями в Москве». Статистика о сотрудниках, проектах и городах отсутствует.

### Проекты

Асимметричная галерея из шести карточек содержит временные нейтральные названия, тип мероприятия и предоставленные роли. Имена реальных клиентов и брендов не выдумываются. Размер карточки задается полем данных, поэтому галерея остается data-driven.

### Процесс

Четыре этапа — заявка, подбор, согласование, мероприятие — расположены горизонтально на широком экране и вертикально на мобильном. Элементы последовательно появляются при прокрутке.

### Финальный CTA и форма

Контрастный желто-черный CTA предваряет форму. Поля формы: имя, телефон, Telegram, дата мероприятия, тип персонала, количество сотрудников и комментарий. Имя и телефон обязательны.

### Footer

Footer содержит логотип, название компании, навигацию и четыре канала связи: телефон, Telegram, WhatsApp и email. Контактные значения централизованы в одном конфиге. До предоставления реальных реквизитов используются явно демонстрационные значения, которые заменяются только в конфиге. Footer содержит строку `© 2026 EVENT CREW. Все права защищены.`

Раздел отзывов полностью отсутствует.

## Фотографии и их замена

Все фотографии первой версии хранятся локально в `public/images`, а не загружаются в браузере со сторонних доменов. Стартовый комплект создается или подбирается в общей стилистике и оптимизируется для веба.

Стабильные имена файлов используются для изображений, которые владелец сайта будет менять чаще всего:

- `hero-event.webp`;
- `services/service-hostess.webp` и аналогичные файлы услуг;
- `projects/project-01.webp` — `projects/project-06.webp`;
- `brand/event-crew-logo.png`.

Замена файла с сохранением имени не требует изменения кода. Если меняется имя, путь обновляется в одном объекте данных. Соотношения сторон документируются и сохраняются контейнерами с `object-fit: cover`, поэтому фотографию можно заменить без изменения верстки.

## Архитектура

Проект использует Next.js App Router, React, TypeScript и Tailwind CSS. Framer Motion допускается только для секций, где CSS недостаточно удобен; большая часть hover-эффектов и плавных состояний реализуется CSS.

Предлагаемое разделение:

- `app/layout.tsx` — корневой layout, metadata и шрифты;
- `app/page.tsx` — композиция секций;
- `app/api/contact/route.ts` — серверная обработка заявок;
- `components/` — Header, Hero, Services, Advantages, Projects, Process, ContactForm, Footer и небольшие переиспользуемые элементы;
- `data/` — услуги, преимущества, проекты, этапы и конфигурация сайта;
- `lib/` — схема валидации, форматирование Telegram-сообщения и небольшие общие функции;
- `public/images/` — логотип и локальные изображения.

Серверными компонентами остаются все статические секции. Клиентскими компонентами становятся только интерактивная шапка, форма и анимационные обертки. Компоненты не знают содержимое массивов: они получают данные и отображают их через четкие props.

## Поток данных формы

1. Пользователь заполняет форму.
2. Клиент проверяет обязательные поля, длину и базовый формат телефона.
3. Во время отправки кнопка блокируется, чтобы исключить повторные запросы.
4. Форма отправляет JSON в `POST /api/contact`.
5. API route повторно валидирует все поля, проверяет honeypot и нормализует значения.
6. Сервер формирует экранированное Telegram-сообщение и обращается к Telegram Bot API с `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` из environment variables.
7. При успехе клиент очищает форму и показывает: «Спасибо! Заявка отправлена. Скоро мы свяжемся с вами.»
8. При ошибке клиент сохраняет введенные данные и показывает: «Не удалось отправить заявку. Попробуйте еще раз.»

Токен и chat ID никогда не попадают в клиентский bundle или ответы API. `.env.example` содержит только имена переменных без секретов.

## Валидация и обработка ошибок

- Имя: обязательная непустая строка с ограниченной длиной.
- Телефон: обязательная строка с допустимыми телефонными символами и минимальным количеством цифр.
- Остальные поля необязательны, но имеют ограничения длины и допустимые значения там, где используется select.
- Количество сотрудников, если задано, является положительным целым числом в разумном диапазоне.
- Некорректный JSON, неверные поля, сработавший honeypot, отсутствие env-переменных, сетевой сбой и отказ Telegram обрабатываются отдельно на сервере и преобразуются в безопасный единый ответ клиенту.
- Технические детали и секреты не показываются пользователю.

## Адаптивность и доступность

- Контрольные ширины уточняются через Tailwind breakpoints; макет проектируется mobile-first.
- На мобильном карточки переходят в одну колонку, этапы процесса становятся вертикальными, а заголовки уменьшаются через `clamp()` без потери иерархии.
- Минимальный размер интерактивной области — 44×44 px.
- Модальное мобильное меню блокирует прокрутку страницы, поддерживает Escape и управление фокусом.
- Все изображения имеют содержательные `alt`, декоративные изображения используют пустой `alt`.
- Контраст текста и кнопок соответствует WCAG AA.
- Горизонтальный скролл не используется и проверяется на узких экранах.

## SEO и производительность

- Один `h1`, логичная иерархия `h2`/`h3`, семантические секции и русская локаль документа.
- Metadata: `Персонал для мероприятий в Москве | EVENT CREW` и описание из требований.
- Настраиваются Open Graph title, description и локальное изображение.
- Локальные изображения отображаются через `next/image`, получают корректные `sizes`; hero использует приоритетную загрузку, остальные изображения загружаются лениво.
- Не подключаются библиотеки, которые не дают измеримой пользы для этого лендинга.

## Проверка результата

- Unit-тесты покрывают серверную схему валидации и форматирование Telegram-сообщения.
- API route проверяется для валидной заявки, ошибок входных данных, отсутствующей конфигурации и отказа Telegram через mock.
- Выполняются TypeScript check, ESLint и production build.
- Страница визуально проверяется как минимум на широком desktop, ноутбуке, планшете и узком мобильном viewport.
- Проверяются burger menu, smooth scroll, состояния формы, отключение анимаций и отсутствие горизонтального скролла.

## Границы первой версии

В первую версию не входят отзывы, CMS, личный кабинет, база сотрудников, аналитическая панель, мультиязычность, вымышленные показатели и интеграции кроме Telegram. Архитектура допускает последующую замену контента и фотографий без добавления этих систем сейчас.
