# Понятное восстановление истории изменений

## Цель

Сделать журнал изменений простым: одно пользовательское изменение занимает одну строку, а восстановление меняет статус этой строки вместо создания новой записи.

## Поведение

- Исходное действие (`изменение`, `удаление`, `порядок`) и его снимки данных сохраняются без перезаписи.
- После успешного восстановления в этой же записи сохраняются дата и пользователь восстановления.
- В интерфейсе строка получает понятный статус «Изменение восстановлено» и пояснение, какие данные были возвращены.
- Кнопка «Восстановить» исчезает; повторно восстановить ту же запись нельзя.
- Неуспешная попытка ничего не меняет ни в контенте, ни в истории.
- Старые записи продолжают работать: новая миграция добавляет необязательные поля восстановления.

## Интерфейс истории

Каждая строка показывает тип объекта, исходное действие, время изменения и краткое описание разницы. Для восстановленной строки дополнительно показываются статус, дата и имя администратора. Фильтр по типу записи сохраняется. Отдельные строки с действием `restore` больше не создаются.

## Подходы

1. Добавить к исходной записи метаданные восстановления — выбранный вариант. Он сохраняет полную историю и не создаёт шум.
2. Перезаписывать исходное действие на `restore` — отклонено, потому что теряется смысл первоначального действия.

## Ограничения

Изменение касается только восстановления через раздел истории. Обычные создания, изменения, удаления и перестановки по-прежнему создают отдельные записи аудита. Уже существующие старые строки `restore`, если они есть, не удаляются автоматически.
